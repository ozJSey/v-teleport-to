- [ ] **`scrollContainer` replaces the window listener instead of adding to it** — OPEN, needs an API
  call. With the default `strategy: 'fixed'` the host's coordinates are viewport-relative, so
  *document* scroll invalidates them unconditionally. `resolveScrollTargets` returns `[element]`
  for a named container, dropping `window` entirely — the host then freezes at its last computed
  viewport position while the page scrolls under it (measured in the playground: reference
  y 484→264, host stuck at 2523). The default listener is already capture-phase on `window`, which
  sees nested containers scroll anyway, so naming a container currently costs page tracking and
  buys nothing but a narrower event surface. Fixing it means always keeping `window` for
  `strategy: 'fixed'` and treating `scrollContainer` as additive, which contradicts the pinned test
  *"array — partially-detached entries are skipped (no window fallback)"*. Playground demos 04/05
  were changed to take the default; the library semantics are unchanged pending this decision.
  (Found during Run 41.)
